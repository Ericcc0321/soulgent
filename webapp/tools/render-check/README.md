# render-check: frontend rendering regression

Runs the real frontend (`web/`) plus the repo's `api/server.py` in headless Chrome. All data is fictional sample data produced by `gen.py` (`samples/` holds the raw attachment files).
Every rendering path is visited once per language (en / hans / hant). A run fails (exit code 1) on an uncaught exception, a `console.error`, an attachment that fails to load, the page showing the "file no longer exists" text, the frontend reporting `k:"err"` to `/api/diag`, or a scenario's own check failing.
Multiple guests: serve.py starts a second guest `guest2` (bound to Web-receipts, prefix [GB]). Scenario `guest2-own-only` (the list shows only its own row; other sessions return 403), `guest2-slash` (/model is blocked: message in all three languages, text stays in the input box and is not sent; /window is sent as usual), `admin-guest2-bubble` (the admin sees the [GB] messages as the second guest's bubble and nickname).
Two scenarios are deliberately exceptions: `image-name` (the 1st embedded image is broken; checks the "file no longer exists" label with "Image 1" and index naming) and `guest-err` (the guest side triggers an error; checks that the request is sent and the entry in diag.jsonl is tagged `account=guest`).

```bash
node tools/render-check/run.mjs                      # all scenarios x three languages, using the repo's web/
node tools/render-check/run.mjs --web /tmp/x/web     # use another copy of the frontend (try changes on a copy before touching web/)
node tools/render-check/run.mjs --only reader-md,chat --langs en -v
node tools/render-check/run.mjs --shots /tmp/shots --tag after   # screenshot every scenario as <scenario>-<tag>-<language>.png
node tools/render-check/run.mjs --md some.md         # attach an external Markdown file (scenario reader-extra) to debug real files
node tools/render-check/run.mjs --list               # list scenarios
```

Requires Google Chrome on the machine (or set the `CHROME` environment variable to its path) and `/usr/bin/python3`. Binds 127.0.0.1 only; temporary data goes in the system temp directory and is deleted after the run.

README screenshots: `gen_readme.py <dir> [en|zh-Hans|zh-Hant]` is a separate clean fictional fixture (Web-redesign etc.; session and zone names are always English, messages/summaries/question cards are generated per language, Traditional Chinese uses Taiwan usage; model names claude-opus-5-5 / claude-sonnet-5-5). Scenarios `readme-list / readme-chat / readme-board` (flagged readme:true; each language gets its own data set and its own serve).
Rendering: `RC_PETS_DIR=<pets dir> node tools/render-check/run.mjs --only readme-list,readme-chat,readme-board --shots <dir>`. Files are named readme-<scenario>-<en|hans|hant>.png; copy and rename them by hand to soulchat-list/chat/board.png.
Avatars use demo pets: `serve.py --pets <dir>` (run.mjs passes the environment variable RC_PETS_DIR through) answers the product's /pets/ API with a manifest and images, only for ids on the DEMO_PETS list in serve.py; soulflame comes from web/figures/soulflame/. Which pet each session uses is set in PETS in gen_readme.py. Without RC_PETS_DIR every /pets/ request returns 404 and all avatars are the built-in soulflame.
Building the pets directory: petdex installs to ~/.petdex/pets and ~/.codex/pets by default (no option to move it). To avoid touching the local machine, run petdex's dist with a temporary HOME (set process.env.HOME in a node script before importing), then slice the result into row strips with `python3 -B -I tools/build_pets.py --src <temp HOME>/.petdex/pets --out <pets dir> --figure ""` (slow: about ten minutes for 19 pets). The pets directory is not committed.
GIF feature wall: `RC_PETS_DIR=<pets dir> node tools/render-check/run.mjs --record /tmp/soulchat-gif [--only soulchat-knock,soulchat-reply,soulchat-tools,soulchat-desktop,soulchat-iphone-still] [--langs en,hans]` records frames (captureScreenshot loop at device scale 2, resampled to constant fps) into `<dir>/<en|zh-Hans|zh-Hant>/frames/<name>/`, using gen_readme.py's `rec` variant (multi-select question, longer Docs-sync history; live changes are really appended to the fixture's transcript and snapshot). Then `python3 -I tools/render-check/encode_media.py /tmp/soulchat-gif` makes the gif (<= 3 MB), mp4 and stills. Media is not committed.
Close-ups (`soulchat-knock-close`, `soulchat-tools-close`, 600 px wide, device scale 3, cropped with the screenshot `clip`): knock-close renders in virtual time (page animations paused and stepped at t = i / fps, infinite ones retimed to whole cycles of the 6 s loop, clock and polling frozen) so the loop is exact; tools-close is real time (one tool runs, the figure climbs on the working bubble, jumps down and parks, then the figure layer fades out; the animations outside the figure layer are locked to one clock, the typing dots held at one pose) so the last frame equals the first. The desktop run uses `gen_readme.py ... rec desk` (longer chat, three more idle sessions). `ENCODE_ONLY=knock-close,tools-close python3 -I encode_media.py <dir>` re-encodes only those folders.
The chat-page scenarios hide, in the screenshot page, the rows covered by the top navigation bar (and the "reached the earliest" notice) so the first visible bubble is complete.
Short WebP clips (800x450 animated WebP q80 + `.poster.jpg`; `encode_media.py` WEBP table): `soulchat-knock-close` (gen_readme.py `kc` variant: Docs-sync is unzoned and busy, its pet cream-cat (serve.py DEMO_CAPS: walk) walks out along the name row; one knock, virtual time, original speed, 3 s), `soulchat-zone-fx` (gen_readme.py `fxz` variant: four busy sessions, one per zone effect), `soulchat-agents-flip` (`flip` variant: three sub-agents, the bubble flips and flips back), `soulchat-tools-close` (one tool run, 2x speed because the figure's walk speed is fixed at 60 px/s). Demo zones carry fx (Web orbit, Docs marquee, Ops halo, Infra circuit) and every session has its own list pet. `ENCODE_ONLY=knock-close,tools-close,zone-fx,agents-flip python3 -I encode_media.py <dir>`.
